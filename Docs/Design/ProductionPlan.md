# 时间主题 Metroidvania Demo 阶段化制作计划（修订版：检查点与死亡重生）

## 一、最终范围

目标为 Windows PC 平台、15～25 分钟的 2D Metroidvania 垂直切片：

- 3 个区域、共 7 个短房间。
- 3 类普通敌人和 1 个两阶段 Boss。
- 玩家能力：移动、跳跃、平砍、空中平砍、Dash、受伤、治疗。
- 时间能力：3 秒全场时缓、5 秒全场时停。
- 1 次能力解锁、1 次旧区域回访、1 个时停升级道具。
- 检查点、死亡重生、基础地图、开始与结束流程。
- 原创像素主角，其他美术使用授权清晰的统一风格素材。

时缓和时停表现为全场效果，但底层不修改全局 `Time.timeScale`，而是通过统一时间接口冻结或减缓世界对象。玩家、UI及明确标记为时间抗性的对象正常运行。

## 二、操作与核心规则

### 键位

| 按键 | 功能 |
|---|---|
| `W/A/S/D` | 上、左、下、右 |
| `J` | 普通攻击；长按蓄力时缓 |
| `K` | 跳跃 |
| `L` | Dash |
| 短按 `I` | 开启时停 |
| 长按 `I` | 蓄力治疗 |
| 时停中按 `I` | 立即提前结束时停 |
| `Esc` | 暂停 |

`W` 用于向上交互和坐检查点椅子；普通房间入口走入即切换房间，不需按键。`S` 用于向下和穿过单向平台；本 Demo 不制作梯子和攀爬系统。

### 普通攻击与时缓输入

- 按下 `J` 时立即进行一次普通攻击，不等待长按判定。
- 如果攻击结束后仍持续按住 `J`，进入时缓蓄力表现。
- 从按下 `J` 开始累计满 1 秒后，时缓准备完成。
- 满 1 秒后松开 `J`，发动持续 3 秒的全场时缓。
- 未蓄满便松开时，只保留最初的普通攻击，不发动时缓。
- 时缓期间按 `J` 仍然可以正常攻击，但不会为下一次时缓提前蓄力。
- 时缓结束后，重新长按 `J` 即可再次发动，没有额外冷却。

### Dash

- Dash 仅提供快速水平位移。
- 没有无敌帧。
- 不能安全穿过敌人、弹幕或攻击判定。
- Dash 撞上敌人攻击时仍会受伤。
- Dash 不能穿过实心墙体。
- 它的价值是快速拉开距离、越过地形和抢占攻击位置，而不是无条件规避伤害。

## 三、时间槽与时间能力

### 时间槽

时间槽参考《空洞骑士》的灵魂槽思路：通过主动进攻积累，再选择用于时停还是治疗。

初始数值：

- 时间槽上限：100。
- 正常时间或时缓期间，平砍命中敌人：恢复 8 点。
- 正常时间或时缓期间，平砍斩掉可破坏弹幕：恢复 4 点。
- 时停期间命中敌人：恢复 2 点。
- 时停期间斩掉弹幕：恢复 1 点。
- 同一次攻击对同一目标只能恢复一次。
- 时间槽不会自然恢复。
- 检查点不主动补充时间槽。
- 玩家死亡重生时恢复满血，时间槽清空。

攻击判定需要同时支持敌人和可破坏弹幕。弹幕被斩后直接销毁，不反弹，也不使用 Graze 擦弹机制。

### 全场时缓

- 长按 `J` 满 1 秒并松开发动。
- 持续 3 秒现实时间，使用 `unscaledDeltaTime` 计时。
- 世界对象时间倍率初始为 `0.35`。
- 玩家和 UI 维持正常速度。
- 时缓不消耗时间槽。
- 时缓期间可以移动、跳跃、攻击和 Dash。
- 时缓期间命中敌人或弹幕，按照正常恢复量补充时间槽。
- 时缓期间不能提前为下一次时缓蓄力。
- 时停可以覆盖时缓：成功开启时停后，当前时缓立即结束。
- 没有足够时间槽开启时停时，时缓继续正常运行。

### 全场时停

基础规则：

- 在非时停状态下短按并松开 `I`。
- 按住时间小于 `0.3` 秒视为短按。
- 开启时固定扣除 60 点时间槽。
- 基础持续时间为 5 秒现实时间。
- 隐藏区域中的升级道具将最长时停时间提升至 7 秒。
- 时停中移动、跳跃和 Dash 不额外扣除时间。
- 每完成一次平砍，从剩余时停时间中额外扣除 `0.6` 秒。
- 时停攻击仍然恢复时间槽，但只有正常恢复量的 25%。
- 时停期间无法发动时缓或治疗。
- 时停归零后自动恢复正常时间。
- 时停期间再次按下 `I`，立即提前结束，不再等待短按判定。

提前结束返还公式：

```text
返还时间槽 = floor(60 × 剩余时停时间 ÷ 本次最大时停时间)
```

其中：

- 未升级时，本次最大时停时间为 5 秒。
- 升级后，本次最大时停时间为 7 秒。
- 平砍额外扣除的 `0.6` 秒同样计入已使用时间。
- 最终时间槽不能超过 100。
- 正常到期时剩余时间为 0，因此不返还。
- 开启后立即取消会返还大部分槽；攻击后取消会因为攻击扣时产生实际成本。

时停伤害结算：

- 时停中攻击敌人时立即记录伤害。
- 敌人不会在冻结状态下移动、击退或播放正常受击动画。
- 时间恢复时统一结算受击、击退和死亡表现。
- 冻结弹幕可以立即被斩掉。
- Boss 会被正常冻结，但少量带紫色提示的“时间锚定攻击”不受时停影响。

## 四、生命与治疗

### 生命规则

- 初始生命为 5 格。
- 普通攻击通常造成 1 点基础伤害。
- 普通敌人攻击通常扣除 1 格。
- Boss 明确标记的重击可以扣除 2 格。
- 受伤后获得约 `0.8` 秒受伤保护，避免同一攻击连续扣血。
- 这段保护属于受伤保护，不属于 Dash 无敌帧。
- 生命归零后回到最近检查点。

### 检查点与死亡重生

- 新游戏以房间 1 起点作为默认复活位置，并建立初始进度；后续检查点必须由玩家靠近后按 `W` 激活。
- 激活检查点时播放明确的视觉、音效和文字反馈，并将最近复活点更新为该检查点；检查点不补充生命或时间槽。
- 坐下休息刷新当前区域的普通敌人；进出房间时刷新离开和进入房间的普通敌人，并清除在场弹幕。
- 生命归零后保持死亡状态约 1.2 秒，再返回最近激活的检查点；尚未激活其他检查点时返回房间 1 起点。
- 重生时恢复满血，时间槽清零，移动速度和击退速度归零，世界时间恢复正常，并清除仍在场的敌方弹幕。
- 死亡只重置死亡所在区域的普通敌人与临时战斗状态，其他区域在本次游玩中的敌人状态不因这次死亡改变。
- Boss 战中死亡时，未击败的 Boss 恢复满血并从第一阶段重新开始；已经确认击败的 Boss 不再复活。
- 已获得的时停能力、7 秒升级、已发现房间及已经确认的 Boss 胜利不因死亡撤销。死亡本身不改变最近检查点，也不触发进度保存。

### 短按时停与长按治疗判定

普通状态按下 `I`：

- 在 `0.3` 秒内松开：尝试开启时停。
- 持续按住超过 `0.3` 秒：不再触发时停，进入治疗准备。
- 进入治疗准备后，再持续蓄力 1.5 秒。
- 从正式治疗蓄力开始，时间槽逐步消耗，共消耗 60 点。
- 因此完整长按时间约为 `0.3 + 1.5 = 1.8` 秒。

治疗限制：

- 开始时必须未满血并至少拥有 60 点时间槽。
- 必须落地并处于正常时间状态。
- 治疗时不能移动、跳跃、攻击或 Dash。
- 松开 `I`、受到伤害、离开地面或进入其他状态都会打断治疗。
- 已经消耗的时间槽不返还。
- 完成后将生命直接补满。
- 满血、时缓或时停状态下长按 `I` 不会消耗资源，并播放不可用反馈。

## 五、阶段化开发流程

### 阶段 0：基础移动——已完成

- 水平移动、跳跃、土狼时间、跳跃缓冲和可变跳高。
- Input System 和移动测试场景。
- 验收：控制稳定，Console 无错误。

### 阶段 1：玩家战斗与状态机

实现：

- 玩家 Prefab、朝向和摄像机。
- 地面平砍、空中平砍、攻击判定。
- 无无敌帧的 Dash。
- 生命、伤害、击退、受伤保护和死亡。
- 玩家状态：正常、攻击、Dash、治疗、受击、死亡。

验收：

- 一次挥剑不会重复伤害同一目标。
- Dash 进入攻击范围时会正常受伤。
- 攻击、Dash、受击和死亡不会卡状态。
- 玩家可以完成移动、攻击、闪避、受伤和重生闭环。

### 阶段 2：时间槽和治疗

实现：

- 时间槽数值与 UI。
- 普通攻击命中敌人后补槽。
- 弹幕斩击和补槽。
- `I` 的 0.3 秒短按/长按识别。
- 1.5 秒治疗、持续扣槽和打断。

验收：

- 短按 `I` 不会误触治疗。
- 长按 `I` 不会先启动时停。
- 治疗被打断时，已消耗资源不返还。
- 满血和资源不足时不会错误扣槽。

### 阶段 3：统一世界时间系统

实现：

- 正常、时缓、时停三种世界时间状态。
- 敌人、投射物、平台、陷阱和 Animator 接入独立时间倍率。
- 3 秒免费时缓。
- 5 秒固定成本时停。
- 时停攻击扣时、低倍率补槽和提前结束返还。
- 5 秒提升至 7 秒的升级接口。

验收：

- 不修改全局 `Time.timeScale`。
- 玩家与 UI 始终正常运行。
- 时缓严格持续 3 秒现实时间。
- 提前结束返还符合公式。
- 攻击造成的扣时会减少返还。
- 不能通过反复开启、攻击、立即关闭获得净时间槽。
- 恢复时间后对象速度、动画和状态正确。

### 阶段 4：敌人和投射物生态

敌人：

- 近战守卫：训练攻击距离和无无敌帧 Dash。
- 高速机械虫：鼓励使用时缓。
- 远程钟弩手：发射可斩弹幕，为时间槽提供主动来源。

实现：

- 巡逻、警戒、攻击、受击和死亡 FSM。
- 投射物对象池。
- 普通、时缓、时停三种状态下的行为。
- 两个混合敌人遭遇。

验收：

- 三类敌人的教学目标不同。
- 玩家不能在安全位置无限刷槽。
- 时停中补槽收益明显低于正常战斗。
- 投射物生成与回收没有持续 GC 分配。

### 阶段 5：七房间关卡与成长

当前七房间仅为玩法验证灰盒，房间几何、入口和地图布局后续由关卡设计替换；普通入口表现为墙体上的真实缺口，主角穿过缺口边界自动换房。未解锁路线允许在缺口处使用实体挡板，解锁后开放。

房间结构：

1. 移动、跳跃、平砍和时间槽教学。
2. 高速敌人与时缓教学。
3. 获得时停能力。
4. 回到旧区域，通过时停打开新路线。
5. 远程敌人、斩弹和资源选择。
6. 隐藏房间，获得 5 秒提升至 7 秒的升级道具。
7. Boss 战与结束流程。

检查点布局：

- `CP_R1_Start`：房间 1 起点，新游戏的默认复活位置。
- `CP_R4_Return`：房间 4 回访路线附近，玩家靠近按 `W` 后激活。
- `CP_R7_Boss`：房间 7 Boss 门外，玩家靠近按 `W` 后激活。
- 每个房间标记所属区域 ID；死亡时依据所在房间的区域 ID 重置该区域的普通敌人。

验收：

- 新玩家能从环境和反馈理解能力。
- 至少有一次能力解锁后的回访。
- 时停升级不是通关必需，但提升效果明显。
- 不设置必须依赖 Dash 无敌帧通过的机关或攻击。

### 阶段 6：Boss 综合考试

两阶段 Boss：

- 第一阶段：近战横扫、跳跃落地、基础弹幕。
- 第二阶段：更快组合、可斩弹幕、时间锚定攻击。
- 时缓用于观察和处理高速攻击。
- 时停用于调整站位、清理弹幕和集中攻击。
- 时间锚定攻击迫使玩家继续移动，不能完全依赖时停。

验收：

- 每个攻击都有清晰前摇。
- 不使用时间能力也能获胜，但难度明显提高。
- 连续时停不能让 Boss 永久失去行动。
- Dash 没有无敌帧时，所有攻击仍有合理躲避路径。

### 阶段 7：测试流程与 UI（当前 Demo 不存档）

当前测试 Demo：

- 实现标题、开始测试、暂停、死亡遮罩、重生和 Boss 结尾流程。
- `Esc` 暂停，`M` 打开基础七房间地图；地图只显示本次运行已发现的房间。
- 检查点仍在交互范围内按 `W` 激活，但只更新本次运行的复活点并刷新对应区域，不写入存档。
- 统一 UI 显示生命、时间槽、时停倒计时、治疗／时缓进度、当前房间、检查点、目标和交互反馈。
- “继续游戏”在标题界面明确禁用；退出 Play Mode、返回标题或重新加载场景都会清空检查点、能力、地图发现和 Boss 胜利状态。
- 不使用 PlayerPrefs，不创建磁盘存档，也不决定 Windows 存档路径或格式。

正式版恢复持久化时沿用既定规则：保存最近检查点 ID、时停解锁、7 秒升级、地图发现和 Boss 击败标记；能力／升级与 Boss 胜利即时保存但不改变复活点，普通敌人状态、弹幕、生命和时间槽不保存。

验收：

- 进入场景先显示标题菜单；开始测试后满血、零时间槽、房间 1 已发现。
- 暂停和地图界面冻结游戏，关闭界面后恢复正常时间与操作。
- 死亡约 1.2 秒后返回本次运行最近检查点，死亡期间显示明确遮罩。
- Boss 胜利进入结尾界面，本次运行中不会复活。
- 重新加载场景只保留默认房间 1 状态，不恢复此前任何测试进度。
- 全流程可以从开始走到 Boss 和结尾。

### 阶段 8：像素美术与反馈

美术规格：

- 采用原创哥特钟表遗迹风格，基础色为冷灰石材、深海军蓝、旧黄铜与暗银，正常时间能量使用青蓝色。
- 战斗提示固定为红色近战、黄色重击、蓝色可斩弹幕、橙色不可斩弹幕和紫色时间锚。
- 正式 Sprite 统一使用 `32 PPU`、Point 过滤、无压缩、关闭 Mipmap；透明素材保存为带 Alpha 的 PNG。
- ChatGPT 原图放入项目根目录 `ArtSource/ChatGPT`，清理后的正式素材放入 `Assets/_Project/Art`，动画控制器与 Clip 放入 `Assets/_Project/Animations`。
- 地图仍由后续关卡设计完成，本阶段只制作三个区域可重复拼接的 `32 × 32` Tile、开放入口墙体断面和视差背景，不生成固定七房间布局。
- 完整提示词、命名、目录和切片规格见 [Phase8GothicClockworkArt.md](../Art/Phase8GothicClockworkArt.md)。

最低动画：

- 待机、跑步、上升、下落。
- 地面攻击、空中攻击。
- Dash、受击、死亡、治疗。
- 时缓蓄力动作或钟表头发光效果。

重点反馈：

- `J` 长按达到 1 秒时必须有明显视觉和音效提示。
- 时缓与时停使用不同色调和声音。
- 时停攻击要显示剩余时间被额外扣除。
- 治疗被打断时需要明确失败反馈。
- Dash 不使用代表无敌的闪烁或透明效果。

验收：

- 主角、三类敌人和 Boss 在正常游戏缩放下只看轮廓也能互相区分，平台边缘不被背景吞没。
- 蓝、橙、紫三类弹幕除颜色外还具有不同外形，色弱或灰度显示下仍能区分处理方式。
- 主角动画单帧为 `96 × 96`，Boss 动画单帧为 `128 × 128`；同一动画内基线、中心和武器长度稳定。
- 空中平砍不改变既有空中速度，Dash 不出现无敌闪烁，时缓蓄力满 1 秒具有明确钟环闪光。
- 三个区域 Tile 可在 `32 × 32` 网格无缝拼接，普通房间入口保持为可穿过的真实墙体缺口。

### 阶段 9：测试、优化与作品包装

测试：

- 不同帧率下检查输入和物理表现。
- 测试短按/长按 `J` 与 `I` 的临界输入。
- 验证所有时停返还组合。
- 验证时停升级后的返还公式。
- 使用 Profiler 检查 CPU、GC、物理和对象池。
- 完成至少三次全流程新存档试玩。
- 验证三个检查点的交互激活、重复激活、死亡回点和退出后继续，且能力或 Boss 胜利的自动保存不更改复活点。
- 验证死亡只重置死亡所在区域的普通敌人；未击败 Boss 从第一阶段重试，已击败 Boss 不复活。
- 验证重生和继续游戏均满血、零时间槽、正常世界时间、无残留弹幕或速度。
- 验证只发现房间而尚未触发保存时，退出重进以最近一次保存的地图发现记录为准。

## 六、核心程序接口

- `IDamageable`：统一玩家、敌人和 Boss 的伤害入口。
- `IHittableProjectile`：标记可以被分针剑斩掉的弹幕。
- `ITimeControllable`：接收正常、减缓和停止状态。
- `WorldTimeService`：管理当前时间模式和全部注册对象。
- `LocalTimeController`：提供对象使用的 `LocalDeltaTime`。
- `TimeGauge`：管理获取、消耗、返还和 UI 事件。
- `TimeStopSession`：记录启动成本、最大时长、剩余时长和返还计算。
- `PlayerCombat`：处理普通攻击、长按 `J` 和攻击命中资源。
- `PlayerHealing`：处理长按 `I`、治疗消耗和打断。
- `HealthSystem`：处理生命、受伤保护和死亡事件；由检查点系统提供复活目标。
- `CheckpointService`：根据稳定检查点 ID 管理交互激活、最近复活点和死亡回点。
- `ProgressSaveService`：保存并恢复永久进度；能力／升级获取或 Boss 胜利时写入，但不改变检查点 ID。
- `ProjectilePool`：使用 Queue 管理弹幕复用。

## 七、准备内容与删减原则

你需要准备：

- GitHub 空仓库。
- 像素绘图工具。
- 主角剪影、钟表头和分针剑设计。
- Tilemap、背景、3 类敌人和 Boss 素材。
- 区域音乐、Boss 音乐和约 10 个基础音效。
- 所有第三方素材的来源与许可证。
- OBS 或其他 1080p 录屏工具。

暂不加入：

- 时间加速。
- 三段连击和多武器。
- Dash 无敌升级。
- NPC、商店、任务和技能树。
- 复杂剧情和大量收集品。

进度不足时优先删减额外收集品、复杂地图表现、装饰动画和完整手柄适配；不删减核心战斗、时缓、时停、治疗、三类敌人、Boss、七个短房间、测试和最终构建。
