# 设计与技术决策记录

## 2026-09-22：项目技术基线

- 锁定 Unity 6.3 LTS（6000.3.24f1），开发期间不升级编辑器主版本。
- 使用 Universal 2D / URP，目标平台为 Windows PC。
- 使用 Unity Input System，不使用旧版 Input Manager 开发核心输入。
- 核心时间玩法采用局部时间方向，不依赖全局 `Time.timeScale`。
- 第一阶段先验证移动和跳跃，不提前锁定武器、攻击方式、时间能力数值或 Boss 设计。
- 玩家状态机暂不创建；等 Dash、攻击、受击等互斥行为出现后，再根据实际状态转换需求设计。

## 范围原则

- 战斗优先于探索，探索优先于解谜，剧情优先级最低。
- 每次只实现一个可测试切片，通过 Unity 内试玩后再扩展。
- 不为了展示设计模式而增加无实际用途的抽象。

## 2026-09-22：第一阶段移动原型

- 先建立独立的 `MovementPrototype` 灰盒场景，只验证水平移动、2D 物理和输入链路。
- `Update` 读取 Input System 输入，`FixedUpdate` 修改 `Rigidbody2D.linearVelocity`，避免把物理写入渲染帧更新。
- Move 动作同时支持 WASD、方向键和手柄左摇杆，当前速度暂定为 7，仅作为首轮手感基线。
- 第一轮不加入跳跃、Dash 或状态机；水平移动经人工试玩确认后再添加跳跃。
- 自动测试确认玩家能够落地、刚体速度归零、移动组件保持启用，且 Console 无错误。
- 基础跳跃使用脚底 `OverlapBox` 与独立 `Ground` Layer 判定落地，避免侧面碰墙也被当作落地。
- 跳跃输入在 `Update` 中缓存，在 `FixedUpdate` 中消费，避免短按输入落在两个物理帧之间而丢失。
- 首轮跳跃速度设为 12；暂不加入土狼时间、跳跃缓冲和可变跳高，等待基础手感测试后再做取舍。

## 2026-09-22：主角视觉基线

- 主角采用适合横版动作游戏的小型角色尺度，屏幕占比参考《空洞骑士》和《铲子骑士》，但不复制其具体造型。
- 头部确定为蓝色钟表造型，武器确定为分针构成的单手剑。
- 正式美术应与物理碰撞和攻击判定解耦；当前 `1 × 1.6` 灰盒尺寸继续作为关卡尺度基线。
- 攻击方式、连招、武器长度和时间能力反馈仍保留，等待战斗系统设计时确定。

## 2026-09-22：跳跃手感完善

- 在基础跳跃通过后加入 `0.1` 秒土狼时间和 `0.12` 秒跳跃输入缓冲，降低临界起跳与落地起跳的操作挫败感。
- 松开跳跃键时削减上升速度，使短按和长按能够形成不同跳高。
- 下落阶段使用额外重力并限制最大下落速度，让腾空过程更利落，同时避免持续加速导致物理穿透风险上升。
- 水平移动继续使用即时响应，优先保证动作战斗和平台跳跃的操控精度；加速度曲线留到人工试玩后再决定。

## 2026-09-23：阶段 1 玩家战斗灰盒

- 引入 PlayerStateMachine 管理正常、攻击、Dash、治疗、受击与死亡六种互斥状态；本阶段先使用其中除治疗外的状态。
- J 的一次平砍使用持续攻击窗口和命中集合，同一挥剑不会对同一 IDamageable 重复结算。
- 地面与空中攻击共享基础伤害，但使用独立判定偏移，为后续动画和空战调参保留空间。
- L Dash 仅改变水平速度并临时关闭重力，不授予无敌；HealthSystem 可以在 Dash 中正常扣血并切入受击状态。
- 统一伤害数据由 DamageInfo 传递，HealthSystem 提供约 0.8 秒受伤保护、击退、死亡事件和检查点重生入口。
- 阶段 1 使用独立 CombatPrototype 场景；训练假人同时提供攻击验收和接触伤害验收，右侧实体墙用于验证 Dash 不能穿墙。
- 核心运行时代码放入 TimeMetroidvania.Runtime 程序集，EditMode 测试单独放入测试程序集。

## 2026-09-23：阶段 2 时间槽与治疗

- 时间槽使用 float 保存，以支持 1.5 秒治疗期间连续扣除 60 点；对外仍以点数展示，并严格限制在 0～100。
- 正常攻击成功伤害敌人后恢复 8 点，斩掉实现 IHittableProjectile 的弹幕后恢复 4 点；无效命中和受伤保护期间的命中不产出资源。
- 玩家死亡通过 HealthSystem.Died 事件清空时间槽，重生不自动补槽。
- I 键按住不足 0.3 秒时发出短按时停请求；达到阈值后只尝试治疗，不会在松开时补发时停请求。
- 治疗要求未满血、至少 60 点时间槽、落地且处于正常状态；进入治疗后锁定移动、跳跃、攻击与 Dash。
- 治疗在 1.5 秒内线性消耗 60 点，松键、受伤、离地或资源异常都会中断，已经消耗的时间槽不返还。
- 时间系统命名空间使用 TimeMetroidvania.GameTime，避免遮蔽 UnityEngine.Time。

## 2026-09-23：阶段 3 世界时间系统

- 世界时间由 `WorldTimeService` 统一仲裁正常、时缓与时停状态，但不修改全局 `Time.timeScale`；受影响对象通过 `LocalTimeController` 获取局部时间倍率。
- J 按下仍立即发动平砍；持续按住满 1 秒后松开，免费触发 3 秒、0.35 倍速时缓。时缓期间不重复蓄力。
- 短按 I 消耗 60 点时间槽启动基础 5 秒时停；升级接口可将单次上限切换为 7 秒，实际升级拾取留到阶段 5。
- 时停覆盖时缓；若时停因未解锁或资源不足而失败，原有时缓继续生效。
- 玩家移动、跳跃、Dash 和攻击不受世界时间倍率影响；时停中每完成一次攻击额外扣除 0.6 秒，命中补槽降为正常值的 25%。
- 时停中再次按 I 会立即结束，并按 `floor(60 × 剩余时间 / 本次上限)` 返还时间槽；自然结束不返还。
- 普通世界对象在时停期间冻结。对冻结目标造成的伤害先由 `TimeAwareDamageReceiver` 缓存，恢复时间后合并结算；冻结弹幕仍可被玩家斩除。

## 2026-09-23：阶段 4 敌人和投射物生态

- 保留 CombatPrototype 作为战斗与时间机制回归场景；新建 EnemyEncounter，串联守卫＋机械虫、机械虫＋钟弩手＋守卫两段遭遇。
- 三类敌人共用巡逻、警戒、攻击、受击、死亡状态机。守卫训练近战距离与 Dash 风险；机械虫使用高速追击与短前摇；钟弩手从远处发射可斩弹幕。
- 敌人的移动、前摇、冷却和受击计时都使用局部时间；时停时不会继续攻击。HealthSystem 在局部时间对象上也使用局部时间计时。
- 钟弩手每次遭遇最多发射 8 发，不依赖无限弹幕提供时间槽；其余敌人死亡后不重生。
- 弹幕对象池在启动时预建并初始化 12 个对象，发射和回收时复用；飞行、寿命和时停均按局部时间推进。

## 2026-09-23：阶段 5 七房间关卡与成长

- 保留阶段四遭遇场景作为回归基线，另建 SevenRoomSlice 单场景灰盒；通过 W 交互门在七个房间间传送，镜头立即对齐目标房间。
- 主线为房间 1→2→3→旧区域房间 1→4→5→7；房间 5 可选进入隐藏房间 6，不取得升级也能抵达 Boss 入口。
- 房间 3 拾取时停能力；回访房间 1 必须真正发动时停才能开启左侧路线。门前储能只补到一次时停所需的 60 点，开门后停用，防止资源耗尽导致软锁。
- 房间 6 拾取 7 秒时停升级。房间 7 仅做 Boss 场地占位，正式 Boss 留到阶段六。
- 房间 1、4、7 的检查点当前只更新本次运行的复活位置；坐下和死亡会刷新对应区域普通敌人，进出房间会刷新离开和进入的房间。走入入口自动换房，隐藏房入口位于跳跃可达侧路；正式地图后续替换当前灰盒。退出后继续和永久进度保存留到阶段七。

## 2026-09-23：阶段 6 Boss 综合考试

- 房间 7 加入 28 点生命的两阶段“时蚀守卫”；一阶段使用横扫、落地重击和基础弹幕，半血后二阶段缩短节奏并加入可斩弹幕和紫色时间锚弹幕。
- 普通行为受世界时间控制；时间锚弹幕抗时停、不可斩。单次时停最多对 Boss 缓存 6 点伤害，防止一轮时停直接跳过完整战斗。
- 玩家死亡会清除 Boss 弹幕并从满血第一阶段重试；Boss 胜利在本次运行中确认后不再因区域刷新复活，永久保存留到阶段七。

## 2026-09-23：阶段 7 测试流程不启用持久化

- 本阶段接入标题、暂停、基础地图、死亡遮罩、统一 HUD 和 Boss 结尾。检查点、地图发现与 Boss 胜利只在当前运行内记录。
- 正式版持久化的数据范围和保存时机继续保留在计划中，待测试 Demo 稳定后再启用；本轮不决定 Windows 存档路径或格式。

## 2026-09-23：阶段 8 原创哥特钟表遗迹美术规范

- 美术方向锁定为原创哥特钟表遗迹，统一使用冷灰石材、深海军蓝、旧黄铜、暗银和青蓝时间能量；不直接模仿现有游戏角色或场景。
- 正式像素素材使用 32 PPU。主角和普通敌人动画使用 96×96 单帧画布，Boss 使用 128×128，Tile 使用 32×32 网格。
- 蓝色可斩弹、橙色不可斩弹和紫色时间锚除颜色外必须使用不同轮廓，保证灰度状态下仍能辨认。
- ChatGPT 原图与 Unity 正式资源分目录保存；正式素材由导入器统一设置 Point、无压缩、关闭 Mipmap 和透明通道。
- 本阶段只提供模块化 Tile、开放入口断面与背景，不固定七房间地图布局，正式地图继续由后续关卡设计完成。
